# Python 工程化与数据持久化

## 模块化架构设计
我的项目分四层：
- core 层：Agent 决策
- audio 层：语音交互
- memory 层：记忆存储
- apps 层：系统操作
分层好处：职责清晰、独立开发测试、模块可替换。

## 配置管理
用 config.py 集中管理配置：API Key、模型名、路径、参数。
好处：配置与代码分离，改配置不用改业务逻辑，方便部署。

## 错误处理
1. 每个工具函数有 try-except 捕获异常，返回友好错误信息
2. 外部依赖（TTS）有重试机制和静默降级
3. 主循环有兜底异常捕获，避免程序崩溃

## SQLite 数据持久化
SQLite 是轻量级嵌入式关系数据库，单文件存储，不需要服务。
用法：存结构化记忆（key-value），支持保存、精确查询、模糊匹配、删除、列表。
对比 MySQL：SQLite 更轻量、零配置，适合单机应用。

## 向量数据库（ChromaDB / FAISS）
ChromaDB：轻量、本地、Python 友好、支持持久化，适合中小规模。
FAISS：Facebook 出品，性能强，但需要自己管理 ID 映射，适合大规模。
我的选择：ChromaDB，因为项目规模不大，需要快速开发。

## 记忆和知识库的区别
记忆 RAG：存结构化信息（邮箱、手机号），按 key 存，用于补充事实。
知识库 RAG：存长文档，按段落切分，用于补充背景知识。
两者用同一个技术栈（ChromaDB + BGE），但 collection 分开。
